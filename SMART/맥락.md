## 4. 작업 방식 · 규칙

- Figma에 쓰기 전에 계획 표 `화면 ID | 위치 | 현재 | 변경 | 근거`를 보여 주고 승인을 받는다
- 다른 사람이 쓴 문구는 승인 없이 고치지 않는다
- 질문은 묶어서 한 번에 하고, 질문마다 추천안을 붙인다
- 사실과 해석을 나눈다. 기준에 없는 것은 TBD / 확인 필요로 둔다
- 용어: 로아스 엔지니어 / 고객사 관리자 / 물류 서버 / 검사 실패
- 맥락 파악을 요청했을 때는 수정 제안을 하지 않는다
- 문구는 히스토리를 모르는 개발자나 신입사원도 이해하도록 쓰되, 간략하게 요점 위주로. 기존 질문의 톤앤매너를 따른다
- 요청한 범위만 손댄다
- 표 정리: 표를 합치지 않고 행은 각각 독립. 라벨은 행마다 하나만. 파란 배경 = 회의에서 확인이 필요하다고 한 항목, 초록 = 사용자가 꼭 넣어야 한다고 표시한 항목
- '개발 요청' 행은 "~하도록 함"으로 끝난다
- 정의서 · 저장소 기준 데이터는 사용자가 나중에 따로 고친다. 그 전에는 손대지 않는다 (11.24)
- Confluence: 초안에만 저장하고 게시하지 않는다. 사용자가 편집 중이면 충돌이 나니 저장 후 새로고침을 요청한다
