**PX-69 이소연 선임 결정 (PX-69 본문 · 댓글, 11.13 Slack)**
- 기본 방향: 로딩이 길어도 사용자가 아무것도 못 하는 상황은 만들지 않는다. 끼어들면 문제가 되는 로딩만 그 시간 동안 막는 데는 동의한다
- 로딩 중 동작
  - 세그먼트를 누르면 진단 카드 데이터는 바로 이동할 영역 기준으로 바뀐다
  - 로딩 중에도 영역 이동, 로봇 선택, NG 선택이 된다. 여러 번 누르면 마지막 것만 적용한다
  - 지금 로딩 중인 영역의 세그먼트를 다시 누르면 변화가 없다
  - 로봇을 누르면 리스트가 바로 닫힌다. 다시 열면 그 로봇 row가 selected 상태다
  - 토스트는 로딩 중에도 생기는 즉시 보여 준다
  - 로봇 패널, 유니티 모달, NG 리스트 패널은 기존처럼 다른 곳을 누르면 닫힌다
- 로딩이 끝난 뒤
  - 세그먼트 이동이나 최초 접속: 기본 줌인 설정이 켜져 있으면 기본 줌인, 꺼져 있으면 기본 시점 (설정 기본값은 off)
  - 로봇을 누른 경우: 그 로봇을 줌인 · 팔로우하고 로봇 패널을 연다. 기본 줌인은 하지 않는다
  - NG를 누른 경우: 그 NG 마커를 줌인하고 유니티 모달을 연다. 기본 줌인은 하지 않는다. 지금은 같은 층 NG만 선택할 수 있다
  - 누른 로봇이 로딩 중에 오프라인이 되면 DSH-001-23a를 보여 준다
  - 누른 NG가 로딩 중에 완료 처리되면 DSH-001-14를 보여 준다
- 기타
  - 기본 줌인은 대기 없이 접속하자마자 Tfoi 정보를 받아 적용한다 (ARQ-584의 5초 제한을 대체)
  - 로딩 문구는 최초 접속과 영역 전환에서 같은 스타일이면 된다. 유니티와 웹 중 누가 구현할지는 PX가 정하지 않는다
  - 맵 없음 메시지 2건은 유니티 메시지 대신 맵 빈 화면 안내로 설계한다
  - 원격제어(수동 이동) 메시지는 v3로 넘긴다
  - v3에서 대시보드 구조가 바뀔 예정이므로 공수는 최소로 들인다

## 4. 작업 방식 · 규칙

- Figma에 쓰기 전에 계획 표 `화면 ID | 위치 | 현재 | 변경 | 근거`를 보여 주고 승인받는다
- 다른 사람이 쓴 문구는 승인 없이 고치지 않는다
- 질문은 묶어서 한 번에 하고, 질문마다 추천안을 붙인다
- 사실과 해석을 나눠 보고한다. 결정 주체가 이소연 선임인 항목은 확인이 필요하다고 표시한다
- **Jira 댓글 · Slack 답글은 초안만 쓰고 등록은 사용자가 직접 한다.** 사용자가 요청할 때만 작성한다. 붙여 넣은 `@이름`은 알림이 가지 않으므로 사용자가 다시 건다
- 댓글 문안은 짧게, 요점만 쓴다. 화면정의서에 이미 있는 내용은 댓글에서 뺀다
- Figma 화면 작업
  - 레이어를 숨기지 말고 삭제한다
  - 사용자가 명시적으로 요청하면 detach해도 된다 (HST-011-13 선례)
  - 패널 위에 얹지 말고 오토레이아웃 구조 안에 넣는다
- Pretendard 제약: Claude의 Figma 환경에는 Pretendard가 없어 Pretendard 텍스트 수정, 텍스트 스타일 적용, Pretendard가 든 프레임을 섹션 안으로 옮기기가 막힌다. 막히면 해당 레이어 링크를 주고 사용자가 직접 처리한다. 정의서 텍스트는 Noto Sans KR이라 Claude가 고칠 수 있다
- `irenelee-gif/SMART_redesign`의 `spec-data/`는 SMART 기준 데이터다. ARQOS 기준이나 미결은 들어 있지 않다
